# 2048 로컬 solver 규칙

- 일반적인 2048 규칙을 기본으로 하되 실제 영상의 보드 구조와 조작 결과를 확인한다. 행·열 및 좌표는 화면에서 추정하고 고정 픽셀 좌표를 사용하지 않는다.
- 타일의 숫자를 인식한다. 동일 색상만으로 같은 값을 단정하지 않는다. 빈칸은 empty, 읽지 못한 숫자는 unknown으로 구분하고 숫자 라벨은 문자열로 반환한다.
- 한 번의 상·하·좌·우 스와이프로 보드 전체 타일이 해당 방향으로 이동한다. 인접한 두 타일을 서로 교환하는 게임이 아니다. 대각선 스와이프를 사용하지 않는다.
- 같은 숫자의 타일 두 개가 이동 방향으로 만나면 합쳐져 두 배의 값이 된다. 한 수에서 새로 합쳐진 타일은 같은 수 안에서 다시 합쳐지지 않는다.
- 네 방향의 이동·합성 결과를 로컬에서 계산하고, 보드를 바꾸지 못하는 방향은 제외한다. 빈칸 확보와 이후 합성 가능성을 고려해 방향을 선택한다.
- 스와이프 시작·끝은 실제 보드 안에 두고 충분한 거리를 확보한다. 특정 타일 두 개를 드래그해 합치는 방식으로 구현하지 않는다.
- 입력 뒤 애니메이션과 새 타일 생성이 끝난 화면을 관찰해 실제 보드 변화를 확인한다. 무효 방향을 같은 상태에서 반복하지 않는다.
- 모든 칸이 찼다는 사실만으로 게임 종료를 판단하지 않는다. 합성 가능한 인접 타일이 남아 있는지 확인한다.
- 메뉴·팝업·다시 시작 버튼은 기존 화면 처리 경로에 맡긴다. 진행 중인 보드를 임의로 초기화하지 않는다.

## 제한된 입력 횟수에서의 진행 평가

- `--steps 50`은 시험 플레이의 입력 횟수 상한이지, 50회 안에 2048 타일을 만들어야 한다는 목표가 아니다. 제한 횟수 안에 2048을 달성하지 못했다는 이유만으로 solver 실패나 수정 필요로 판단하지 않는다.
- 시험에서는 로컬 solver가 유효한 방향을 선택하고, 입력 후 실제 타일 이동·합성 등 보드 변화가 지속되는지 평가한다. 점수나 최대 타일 값 상승은 확인 가능할 때 추가 진행 근거로 사용한다.
- ADB 입력 성공만으로 유효한 수로 간주하지 않는다. 입력 전후 보드를 비교하고, 변화 없는 방향의 반복·잘못된 인식·게임 오버·복구 의존 여부를 별도로 기록한다.
- 마지막 입력 뒤 후속 관측이 없으면 그 입력의 결과는 미확인으로 둔다. 추측해서 성공이나 실패로 계산하지 않는다.
- 클리어 여부, 제한 횟수의 정상 실행 완료, 로컬 solver의 진행 능력은 별도로 기록한다. 2048 타일 생성이나 승리 화면을 관측하지 않았다면 클리어했다고 보고하지 않는다.
- 화면 분류용 모델 호출과 VLM이 대신 선택한 보드 입력을 구분한다. VLM 보드 복구로 얻은 진행은 로컬 solver만의 성공으로 계산하지 않는다.
- 수정은 관측된 인식 오류·무효 동작·진행 정체를 근거로 수행한다. 단순히 클리어 횟수가 0이라는 이유로 정상 동작하는 solver를 재작성하지 않는다.

이 문서는 매 생성·수정 요청에 전달되는 지침이다. 실행기에도 game_2048 전용 진행 판정을 반영했다: 인식 검증 통과, 실행 정상 종료, 로컬 입력 3회 이상, 확인된 보드 변화 2회 이상, 입력 오류 및 VLM 보드 복구 0회를 요구하며 클리어는 요구하지 않는다. 이 기준은 제한된 시험의 로컬 진행 검증이지 2048 달성 또는 고득점 보증이 아니다.
